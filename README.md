# Project Novelty Detector - Frontend

A clean, professional Streamlit application for analyzing research project novelty and suggesting improvements.

## 🚀 Features

- **Student Authentication**: Login with sample credentials (frontend demo mode; see Security Notes)
- **Project Dashboard**: Quick overview of submitted projects and statistics
- **Project Submission**: Comprehensive form to submit project details
- **Novelty Analysis**: Similarity-based analysis of project novelty (see "How the analysis works" below)
- **Novelty Suggestions**: Get personalized, rule-based recommendations to enhance your project
- **Project Management**: View and manage all submitted projects
- **Professional UI**: Clean, modern, responsive design

## 🧠 How the analysis works

The novelty analysis (`novelty_engine.py`) is a **rule-based similarity engine**, not a
trained machine-learning model. It computes a weighted score from:
Jaccard similarity on technologies/keywords (set overlap) + string similarity on
domain/method/dataset (exact match, substring match, or token overlap). Suggestions are
generated by filling rule-based templates with whatever overused components, limitations,
and gaps the similarity pass turns up. This is a legitimate, explainable approach for a
course project -- just don't describe it as "AI-powered" or "ML-based," since there's no
trained model or embeddings involved. `BACKEND_DOCUMENTATION.md` lists adding real
embeddings-based similarity as a future enhancement.

## 📋 Application Flow

1. **Login Page** - Student authentication
2. **Dashboard** - Project overview and navigation
3. **Project Submission** - Enter project details
4. **Analysis** - Backend analysis with loading state
5. **Novelty Results** - Main page showing analysis results (similar projects, suggestions, gaps)
6. **Select & Save** - Confirm project with selected novelty idea
7. **My Projects** - View all submitted projects
8. **Project Details** - Complete project information and analysis

## 🛠️ Installation & Setup

### Prerequisites
- Python 3.8+
- pip

### Installation Steps

1. **Navigate to the project directory:**
   ```bash
   cd project-novelty-detector
   ```

2. **Create a virtual environment (recommended):**
   ```bash
   python -m venv venv
   # On Windows
   venv\Scripts\activate
   # On macOS/Linux
   source venv/bin/activate
   ```

3. **Install dependencies:**
   ```bash
   pip install -r requirements.txt
   ```

## 🎯 Running the Application

```bash
streamlit run app.py
```
or equivalently:
```bash
streamlit run app_single_file.py
```

The application will start on `http://localhost:8501`

`app.py` and `app_single_file.py` are two entry points to the **same** implementation:
`app.py` simply imports and calls `main()` from `app_single_file.py`, which is the single
source of truth for the frontend (see "Project Structure" below for why). Both use the demo
accounts below without connecting to MySQL. Email and username ignore surrounding spaces and
capitalization; passwords must match exactly. If these credentials are rejected, restart
Streamlit from this project directory and re-enter the password.

After login, use **Dashboard**, **My Projects**, or **Create New Project** in the sidebar.
**View Full Details** opens project information from the dashboard or project list. If an
older sidebar is still displayed after updating, restart Streamlit and open
`http://localhost:8501` without a page suffix.

## 💾 Data Management

By default, the frontend (`app_single_file.py`) uses hardcoded sample data (students,
projects, similar-project matches, novelty ideas) defined at the top of the file, and does
**not** require MySQL or the Flask backend to run. For real, persistent data backed by
MySQL, run `backend.py` (see `BACKEND_DOCUMENTATION.md`) and wire the frontend's
`authenticate_user()` / project-submission calls to the REST endpoints it exposes instead of
the sample data.

## 🔄 Navigation

The application uses Streamlit's session state for navigation:
- `st.session_state.logged_in` - User authentication status
- `st.session_state.current_page` - Current page
- `st.session_state.project_form_data` - Form data during submission
- `st.session_state.analysis_results` - Analysis results
- `st.session_state.selected_novelty` - Selected novelty idea

## 🔐 Security Notes & Known Limitations

⚠️ **Important** -- this is a course/demo project, not a hardened production system.
Specifically:
- The frontend demo login checks credentials against an in-memory dict
  (`SAMPLE_STUDENTS`) -- it is not connected to the database by default.
- When the Flask backend *is* used, `/api/auth/login` returns the student's profile but
  issues **no session token**. Every other backend endpoint trusts whatever `student_id` is
  passed in the request body, so there is no real per-request authorization. Adding
  JWT-based session tokens is listed as a future enhancement in `BACKEND_DOCUMENTATION.md`.
- Backend passwords are hashed with Werkzeug's salted PBKDF2 hasher
  (`werkzeug.security.generate_password_hash`), which is adequate for a course project but
  you should not reuse this exact setup for anything handling real user data without adding
  HTTPS, rate limiting, and token-based auth.
- The novelty-analysis engine is rule-based similarity scoring, not a trained ML model (see
  "How the analysis works" above) -- don't describe it as "AI-powered" in a report or demo.

For an actual production deployment you would additionally want: HTTPS/SSL, backend-side
input validation beyond required-field checks, rate limiting, and a real session/JWT layer.
